FlockBoard — App Map

Snapshot after 5-build. Local desk router: paste a messy task → role + one-line brief + yes/no. No cloud.

What it is

One static page. A small rules engine in JavaScript scores keyword/phrase signals for four roles (ops, marketing, research, code), picks the highest score (fixed tie-break), and paints a routing card. Human Yes/No stays in the loop; Copy puts the brief on the clipboard when allowed.

One action through the system

Visible result: a desk card with one of four roles and a copyable brief.

Reference route (3 stops)

  1. index.html — #task, #route-btn, #card: paste surface and card markup.
  2. app.js — route(taskText): normalize, score SIGNALS, pick role, build brief.
  3. app.js — mount(document) handlers for Route / Yes / No / Copy: card state idle | ready | accepted | rejected.

To change this, start here

  • Role keywords → SIGNALS in app.js; re-run node smoke_test.js and update SAMPLES.md.
  • Brief wording → VERBS / oneLineBrief in app.js.
  • Look and feel → styles.css (--accent, card layout).
  • Empty-submit copy → onRoute message in mount.

A practice to reuse

The kernel was a single observable card (role + brief + yes/no). Spec locked heuristics instead of a paid LLM; smoke_test.js + SAMPLES.md turned that unknown into eight checked examples. Next time: name the filmable beat first, then verify the risky assumption with a tiny script—not a framework.
